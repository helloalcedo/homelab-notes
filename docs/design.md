# 디자인 기준

## 1. 방향

`Alcedo`는 물총새의 속(屬) 이름이다. 물 위에서 오래 관찰하다가 한 번에 정확하게 잠수하는 새를 "끝까지 파고드는 기록"의 상징으로 쓴다.

화면은 사용자가 제공한 참고 사이트처럼 단순하게 유지한다. 짙은 먹색 바탕, 작은 모노 라벨, 넓은 여백, 왼쪽의 짧은 문장이 기본이다. 그림·도식·윤곽·아이콘·수면 같은 시각 요소는 모두 하나의 입자 풀로 그린다. 문장과 링크, 입력은 HTML이 맡아 선택·복사·보조기기 읽기가 가능하게 한다.

색은 참고 사이트의 먹·종이 팔레트를 유지한다. 물총새만 코발트·하늘색 깃털과 주황 가슴을 가진다. 실제 물총새가 강가에서 "푸른 섬광"으로 보이듯, 절제된 화면에 한 번 나타나는 파란색이 정체성이 된다. 녹슨 주황 강조색은 물총새 가슴색과 같은 계열이다.

홈 밖의 프로젝트·노트·소개·검색·개별 글은 정적인 기술 저널이다. 홈의 움직임과 별개로 URL을 직접 열어 읽고 인쇄하고 공유할 수 있어야 한다.

## 2. 화면 체계

### 색

| 역할 | Ink (기본) | Paper |
| --- | --- | --- |
| 바탕 `--bg` | `#141413` | `#eeeadf` |
| 본문 `--fg` | `#e8e6dc` | `#242420` |
| 보조 `--muted` | `#a3a199` | `#646158` |
| 흐림 `--faint` | `#6f6d66` | `#8f8b80` |
| 구분선 `--line` | `#33332e` | `#c9c3b6` |
| 강조 `--accent` (가슴 주황) | `#c88169` | `#995139` |
| 섬광 `--flash` (물총새 하늘색) | `#4cc4e8` | `#11769a` |

`--flash`는 물총새, 잠수 궤적, 현재 위치 표시처럼 "지금 여기"를 가리키는 곳에만 쓴다. 글자 대비는 WCAG AA(4.5:1)를 맞추고 `--faint`는 장식선과 보조 눈금에만 쓴다.

### 글꼴

- `Alcedo`, 영문 장식 제목: Instrument Serif regular·italic (자체 호스팅)
- 한국어 제목·본문: Noto Serif KR WOFF2 유니코드 서브셋 (자체 호스팅)
- UI: 시스템 산세리프, 라벨·번호·메타데이터: 모노스페이스

홈 장면의 라벨은 8–10px 모노, 제목은 30–42px 세리프, 설명은 12–13px로 참고 사이트의 비율을 따른다.

## 3. 홈: 여섯 장면

모든 장면은 전체 화면에 고정된 하나의 canvas와 같은 입자 풀을 쓴다. 문서는 긴 scroll track을 제공하고, 스크롤 비율을 0–5.82의 장면 진행값으로 바꾼다. 오른쪽 장면 레일(모바일은 하단)과 URL hash가 같은 여섯 장면을 가리킨다.

| 장면 | 수심 | 입자가 그리는 것 | HTML |
| --- | --- | --- | --- |
| 00 수면 | 0m | 가운데의 제목 `Alcedo`, 오른쪽 아래 가지와 작은 물총새, 수면선, 수면 아래 반짝임, 수면 반영, 물보라, 공중의 먼지 | 제목 `Alcedo`(입자 제목이 준비되면 투명) |
| 01 홈랩 | −12m | 네트워크 트리. 가지를 따라 흐르는 입자, 분기점 노드, 선택된 경로, 끝단 원 | 문장, 주제, 링크, 개념도 캡션 |
| 02 프로젝트 | −24m | 프로젝트 위젯. 카드 테두리, 머리줄 구분선, 상태 점, `BUILD → VERIFY → DEPLOY` 파이프라인, 기술 칩, 두 버튼 | `hugo.toml` 코드, 제목, 요약, 링크 |
| 03 노트 | −36m | 노트 두 장. 접힌 모서리, 괘선, 체크 상자와 체크 표시, 두 열로 나뉜 두 번째 노트 | 번호, 제목, 요약, 링크 |
| 04 발행 | −48m | 실험 → Hugo·Velog·GitHub → 기록. 문서·말풍선·`</>`·물결 아이콘, 흐르는 신호 | 노드 이름 |

첫 화면에는 가운데의 입자 제목 `Alcedo`와 오른쪽 아래 가지에 앉은 작은 물총새만 보인다. 제목은 원래 홈과 같은 Instrument Serif italic, 글자 크기 9.58vw(모바일 22.5vw)로 래스터화한 좌표를 쓴다. 헤더와 장면 레일은 수면을 벗어난 뒤 나타난다. 부리 끝에서 약 4.6초마다 물방울이 떨어져 수면에 파문을 만들며, 아래로 내려가라는 신호가 된다.

물총새는 장면 형태와 별개인 동반자다. 입자 풀의 14%(최소 360개: 데스크톱 2,660개, 모바일 1,400개, Canvas 대체 360개)를 자기 몫으로 쓰고, 장면 사이의 순위 대응에 들어가지 않는다. 각 장면에서는 실제 HTML 요소의 위치를 측정한 자리에 앉는다: 01 네트워크 뿌리 노드, 02 프로젝트 카드 윗변, 03 두 번째 노트 윗변, 04 `기록` 노드. 05에서는 검색 알약 속으로 잠수해 사라진다. 새의 크기는 데스크톱에서 너비의 9.5%(118–165px), 모바일에서 27%이며 화면 높이의 26%를 넘지 않는다.

## 4. 잠수와 동행 (00 → 05)

모든 움직임은 스크롤 진행값에 묶여 되감을 수 있다. 날갯짓과 숨쉬기만 시간에 따라 움직여서, 비행 중에 스크롤을 멈추면 새가 멈춘 그림이 되지 않고 제자리에서 날갯짓한다(물총새의 정지 비행). 아래 진행값은 각 장면 안의 비율이다.

1. 00의 0–0.08: 가지 위에서 숨 쉬듯 움직이고, 머리가 포인터 쪽으로 조금 기울며 꼬리가 흔들린다.
2. 0.08–0.27: 고개를 숙여 수면을 내려다보고, 꼬리를 한 번 튕긴 뒤 몸을 낮춘다. 가지가 무게만큼 휜다.
3. 0.27–0.36: 가지를 박차고 수면 위로 솟아 잠깐 정지 비행한다. 떠난 가지는 튕겨 흔들린다.
4. 0.36–0.47: 급강하. 몸이 궤적의 접선을 따라 돌아 입수 직전에는 수평에서 약 80° 아래를 향하고, 머리는 궤적보다 조금 먼저 숙인다. 날개는 뒤로 젖혔다가 몸에 붙이고, 몸의 앞쪽만 1.34배 늘리고 폭을 0.8배로 좁혀 화살 모양이 된다. 뒤쪽 입자는 궤적을 따라 조금 늦게 따라와 속도감을 만든다.
5. 0.47: 부리가 정해진 입수점에 닿는다. 몸은 속도를 줄이며 계속 들어가고 수면선에서 잘린다. 잠긴 입자의 약 1/3은 물보라가 되어 구멍 가장자리에서 양쪽으로 튀고, 조금 뒤 가운데에서 짧은 물기둥이 솟는다. 수면선은 고리 모양으로 솟았다 가라앉고 파문이 퍼진다.
6. 0.58–0.66: 입수점 앞쪽 수면을 뚫고 거의 수직으로 솟구친다. 날개는 수면을 벗어나면서 펴지고, 두 번째 물보라가 인다.
7. 0.66–1.00: 날갯짓하며 01의 뿌리 노드로 날아가 착지한다. 제목 입자는 0.72부터 네트워크 트리로 흩어진다.
8. 01–03의 0.72–1.00: 몸을 낮췄다 도약하고, 호를 그리며 날아가 다음 자리에 착지한다. 진행 방향이 바뀌면 이륙할 때 몸을 돌리고, 착지하면 다시 문구 쪽을 본다. 몸 기울기는 상승·하강 각도의 60%만 따른다(최대 ±0.35rad).
9. 04의 0.72 → 05: `기록` 노드에서 이륙해 검색 알약 위로 올라갔다가(비행의 62%) 약 83°로 알약 윗변에 잠수한다. 윗변 아래는 잘리고 잠긴 입자 일부가 물보라가 된다. 나머지 입자는 입수점에서 양쪽으로 테두리를 따라 달리는 하늘색 파문이 되어 아래에서 만나며 사라진다(05의 0.012–0.23). 05 문구는 새가 들어간 뒤(5.01–5.17)에 나타난다.

착지는 날개를 들어 앞으로 젖히고(제동), 발을 내리고, 꼬리를 편 뒤 날개를 접는다. 날개는 접힌 날개 윤곽을 어깨를 축으로 회전·신장해 만든다. 옆에서 본 날갯짓을 "상하 각도·뒤로 젖힘·길이" 세 값으로 정하므로, 날개가 관람자 쪽으로 펼쳐지는 순간은 짧게(단축되어) 보인다. 날갯짓 한 번은 240ms이고 내려치기가 42%를 차지하며, 내려칠 때 몸이 조금 뜬다. 날개 표본의 42%는 몸에 남아 날개가 들렸을 때 드러나는 등(하늘색)과 옆구리(주황)를 채우고, 날개가 아직 덮는 부분에서는 날개 색으로 보인다.

동작 줄이기에서는 각 장면의 정지 위치(앉은 자세)만 보여주고, 05의 정지 위치에서는 새가 보이지 않는다.

## 5. 입자 모핑 엔진

- **대응:** 장면마다 입자에 자리를 배정할 때, 이전 장면의 위치와 다음 장면의 자리를 x 분위로 나눈 띠 안에서 y 순서로 짝짓는다(Knothe–Rosenblatt 방식). 가까운 입자는 가까운 자리로 가고, 경로가 서로 엉키지 않는다. 대응은 레이아웃이 바뀔 때만 다시 계산한다.
- **경로:** 입자마다 공간 위치에 따른 출발 시차가 있다. 이동은 시작과 끝의 속도·가속도가 0인 5차 곡선을 따르고, sin(πt) 크기의 곡선 편차와 느린 흐름장이 더해진다. 도착하면 편차가 사라져 흔들리지 않는다.
- **구멍 없음:** 크기·밝기·색은 두 장면의 재료 값 사이에서만 보간한다. 전환 중에 입자를 투명하게 해서 이동을 가리지 않는다.
- **스크롤 평활화:** 스크롤 진행값을 임계 감쇠 스프링으로 따라가게 한다. 입자·문구·장면 레일이 같은 값을 쓴다. 스크롤을 가로채거나 스냅하지 않는다.
- **상호작용 변위:** 포인터 반발과 클릭 파문은 형태 위의 별도 변위 스프링으로 더한다. 형태 자체는 항상 정확하다.
- **반영:** 00 장면에서는 같은 입자 버퍼를 수면 기준으로 한 번 더 그린다. 반영은 아래로 갈수록 흐려지고 물결을 따라 흔들린다.
- **동반자:** 물총새 입자는 장면 슬롯 대신 리그(위치, 기울기, 방향, 날개·머리·꼬리 각도, 유선형 비율, 잘림선)를 따른다. 진행값의 매 프레임에 리그를 한 번 계산하고, 잠수 중에는 조금씩 늦은 진행값의 리그 다섯 개를 몸의 앞뒤 위치로 섞어 잔상을 만든다.
- **대체:** WebGL을 쓸 수 없으면 Canvas 2D의 1,800개 입자로 같은 장면을 그린다. 둘 다 실패하면 여섯 장면을 일반 문서 흐름으로 되돌린다. 동작 줄이기에서는 각 장면의 정지 형태만 그린다.

## 6. 문구와 크롬의 움직임

- 장면 문구는 장면 진행값에 묶인다. 들어올 때는 줄 단위로 가려진 채 아래에서 올라오고, 나갈 때는 위로 조금 흐르며 사라진다. 역방향 스크롤에서는 같은 경로를 되감는다.
- 02 장면의 코드는 위에서 아래로 드러나고, 위젯 내용은 입자 테두리가 완성된 뒤 나타난다.
- 장면 레일에는 현재 장면의 선이 길어지고 수심이 함께 표시된다.
- 입력과 링크를 조작하는 동안 장면 키보드 명령(방향키, Page Up/Down, Home, End)은 가로채지 않는다.

## 7. 정적 기록 페이지

- 목록은 번호, 제목, 요약, 날짜의 편집형 아카이브다. 행 전체가 링크이며 hover·focus에서 번호와 화살표가 반응한다.
- 글은 760px 안팎의 읽기 폭, sticky 목차와 현재 절 강조, 상단 읽기 진행선, 복사 가능한 코드와 주소, 스크롤 가능한 표를 제공한다.
- 페이지 이동은 View Transitions를 지원하는 브라우저에서 목록의 제목이 글 제목으로 이어지고, 헤더는 그대로 남는다. 참여 규칙(`@view-transition`)은 조건 없이 두고, 동작 줄이기에서는 애니메이션만 없애 즉시 바뀌게 한다. 참여 규칙을 미디어 쿼리 안에 두면 새 문서에서 판정이 늦어 전환이 취소될 수 있다.
- 헤더는 얇게 고정되고 아래로 읽을 때 물러났다가 위로 올리면 돌아온다. 푸터 구분선 위에는 입자 물총새가 앉아 포인터 쪽으로 고개를 돌리고, 닿으면 깃털이 흩어졌다 돌아온다. 소개와 404에는 수면 위의 물총새가 대신 앉는다.
- 기록 번호는 섹션 안에서 오래된 순서로 매기며 홈·목록·글에서 같다.
- 검색은 ⌘K·Ctrl+K·`/`로 여는 대화상자와 `/search/` 페이지가 같은 결과를 쓴다. 검색어를 강조하고 방향키로 결과를 오간다.
- 320px에서도 긴 코드·URL·표 때문에 문서 전체가 가로로 넘치지 않아야 한다.

## 8. 글 읽기 전환

홈에서 글을 열면 현재 장면의 입자가 실제 제목·설명·본문 글자의 획으로 모인 뒤, 같은 위치의 HTML 본문으로 이어진다. `article-glyphs.js`가 보이는 글자만 측정해 좌표를 만들고, 전환 시간은 `reader-motion.js`가 공유한다. 노트의 이전·다음 이동은 기존 글자가 입자로 흩어졌다가 다음 글의 획으로 모인다. 주소·제목·canonical은 글에 맞게 바뀌고 Back/Forward가 글과 읽던 위치를 복원한다. 샘플링에 실패하면 HTML끼리 교차해 나타나는 전환으로 대체한다.

## 9. 성능과 접근성

- 입자는 데스크톱 19,000개, 모바일 10,000개, Canvas 대체 1,800개이고, 그중 9%는 먼지, 14%(360–3,000개)는 물총새다. 기기 픽셀 비율은 최대 2로 제한한다. 탭이 숨겨지거나 읽기 화면이 열리면 RAF를 멈춘다.
- canvas는 `aria-hidden`이다. 현재 장면이 아닌 section은 `inert` 처리해 초점이 들어가지 않게 한다.
- 프로그램으로 옮긴 제목 초점에는 장식 테두리를 그리지 않는다. 키보드 초점은 항상 보인다.
- JavaScript가 없으면 여섯 장면이 일반 문서로 읽히고, 모든 글은 정적 URL로 열린다.

## 10. 검증 기록

아래 항목은 실제로 실행한 검증만 적는다. 실행하지 않은 기기·브라우저는 검증 범위로 주장하지 않는다.

모든 기록은 macOS의 Google Chrome(헤드리스, playwright-core 1.63)과 ANGLE Metal WebGL(Apple M3 Pro)에서 확인했다.

### 2026-09-28 2차: 가운데 제목과 따라오는 물총새

- **첫 화면:** 원래 홈(`main`)을 따로 빌드해 1440×900 첫 화면을 캡처하고, 새 첫 화면의 `Alcedo` 크기·위치가 같음을 비교했다.
- **잠수:** 1440×900에서 00의 0–1.0을 약 40개 진행값으로 캡처하고 새 주변을 확대했다. 이 과정에서 날개를 들 때 몸통에 구멍이 나는 문제, 급강하가 약 55°에 그치는 문제, 꼬리가 바늘처럼 늘어나는 문제, 잔상 단계 경계에 어두운 줄이 생기는 문제, 물보라가 원뿔처럼 보이는 문제를 발견해 고쳤다.
- **동행:** 1440×900에서 1→2, 2→3, 3→4 비행과 04→05 잠수(4.92–5.3)를 프레임 단위로 캡처했다. 이륙 직후 공중에 서 있는 듯한 자세, 05 제목을 새가 가로지르는 문제, 알약 파문이 테두리 입자에 가려 보이지 않는 문제를 고쳤다. 390×844(DPR 2), 320×568(DPR 2), 844×390(DPR 2), 1024×768에서 정지 위치와 잠수·파문의 주요 프레임을 캡처했고, 844×390에서 새가 헤더에 가까운 문제를 높이 제한으로 고쳤다.
- **성능:** 0에서 5.3까지 스크롤하는 동안의 프레임 간격은 1440×900과 390×844(DPR 2) 모두 중앙값 16.7ms, 99번째 백분위 16.8ms였다. 이 기기의 헤드리스 측정이며 실제 휴대폰의 성능은 확인하지 않았다.
- **회귀:** 종이 테마, 동작 줄이기, Canvas 2D, JavaScript 끔, 읽기 전환(열기·넘기기·Escape 복귀), 정적 페이지 18조합, 정적 페이지 간 View Transition 6회, 장면 레일로 05 이동, `수면으로 ↑`, `#notes`·`#explore` 딥링크에서 콘솔 오류는 0이었다.
- **빌드:** `make check`를 통과했다.

### 2026-09-28 1차: 가지 위의 큰 물총새와 트리로 이어지는 잠수

아래는 이번 변경 전 설계(첫 화면에 큰 물총새만 두고, 잠수한 몸이 네트워크 트리가 되는 방식)의 기록이다.


- **홈:** 1440×900, 1024×768, 390×844(DPR 2), 320×568(DPR 2), 844×390(DPR 2)에서 여섯 장면의 정지 형태를 캡처했다. 1440×900과 390×844에서는 잠수 구간(데스크톱 0.40–0.93, 모바일 0.47–0.80)과 1→2, 2→3, 3→4, 4→5 전환의 중간 프레임도 캡처했다. 데스크톱은 19,000개, 모바일은 10,000개 입자였고 이 기기에서 측정된 값은 60fps였다. 모든 기기에서 같은 성능을 보장하는 값은 아니다. 좁은 화면의 잠수가 화면 밖으로 나가는 문제, 844×390의 노트 겹침과 레일 겹침을 발견해 고쳤다.
- **대체 경로:** 종이 테마와 동작 줄이기(정지 장면, RAF 정지)를 확인했다. WebGL을 끄면 Canvas 2D의 1,800개 입자로 바뀌었다. JavaScript를 끄면 여섯 장면이 일반 문서 흐름으로 표시되었다.
- **읽기 전환:** 홈 노트 장면에서 글 열기, 다음 노트로 넘기기, 읽기 진행선과 현재 목차 표시, Escape로 `#notes`에 돌아오는 흐름을 확인했다. 이전에 글자를 측정할 때마다 나던 `CanvasFontStretch` 경고를 포함해 콘솔 오류와 경고는 0이었다.
- **정적 페이지:** 프로젝트·노트·소개·검색·글 두 개·주제 목록·주제·404를 1440×900과 390×844에서 캡처했다. 가로 넘침과 콘솔 오류는 0이었다. 검색어 강조, 방향키 이동, 테마 전환, 목록과 글 사이 이동을 확인했다. 정적 페이지 간 이동 30회에서 View Transition 취소는 0회였다.
- **빌드:** `make check`로 Python 테스트 4개, Hugo 프로덕션 빌드, HTML 18쪽의 링크·자산·canonical·sitemap 검사를 통과했다.

Safari, Firefox, 실제 iOS·Android 기기, 스크린리더 음성 출력과 GitHub Pages 배포는 이번 검증에 포함하지 않았다.
