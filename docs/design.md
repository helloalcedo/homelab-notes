# 디자인 기준

## 1. 방향

`Alcedo`는 물총새의 속(屬) 이름이다. 물 위에서 오래 관찰하다가 한 번에 정확하게 잠수하는 새를 "끝까지 파고드는 기록"의 상징으로 쓴다.

화면은 사용자가 제공한 참고 사이트처럼 단순하게 유지한다. 짙은 먹색 바탕, 작은 모노 라벨, 넓은 여백, 왼쪽의 짧은 문장이 기본이다. 그림·도식·윤곽·아이콘·수면 같은 시각 요소는 모두 하나의 입자 풀로 그린다. 문장과 링크, 입력은 HTML이 맡아 선택·복사·보조기기 읽기가 가능하게 한다.

색은 참고 사이트의 먹·종이 팔레트를 유지한다. 물총새만 코발트·하늘색 깃털과 주황 가슴을 가진다. 실제 물총새가 강가에서 "푸른 섬광"으로 보이듯, 절제된 화면에 한 번 나타나는 파란색이 정체성이 된다. 녹슨 주황 강조색은 물총새 가슴색과 같은 계열이다.

홈 밖의 프로젝트·노트·소개·검색·개별 글은 정적인 기술 저널이다. 홈의 움직임과 별개로 URL을 직접 열어 읽고 인쇄하고 공유할 수 있어야 한다.

## 2. 화면 체계

### 색

| 역할 | Ink (기본) | Paper |
| --- | --- | --- |
| 바탕 `--bg` | `#141413` | `#eeeadf` |
| 본문 `--fg` | `#e8e6dc` | `#242420` |
| 보조 `--muted` | `#a3a199` | `#646158` |
| 흐림 `--faint` | `#6f6d66` | `#8f8b80` |
| 구분선 `--line` | `#33332e` | `#c9c3b6` |
| 강조 `--accent` (가슴 주황) | `#c88169` | `#995139` |
| 섬광 `--flash` (물총새 하늘색) | `#4cc4e8` | `#11769a` |

`--flash`는 물총새, 잠수 궤적, 현재 위치 표시처럼 "지금 여기"를 가리키는 곳에만 쓴다. 글자 대비는 WCAG AA(4.5:1)를 맞추고 `--faint`는 장식선과 보조 눈금에만 쓴다.

### 글꼴

- `Alcedo`, 영문 장식 제목: Instrument Serif regular·italic (자체 호스팅)
- 한국어 제목·본문: Noto Serif KR WOFF2 유니코드 서브셋 (자체 호스팅)
- UI: 시스템 산세리프, 라벨·번호·메타데이터: 모노스페이스

홈 장면의 라벨은 8–10px 모노, 제목은 30–42px 세리프, 설명은 12–13px로 참고 사이트의 비율을 따른다.

## 3. 홈: 여섯 장면

모든 장면은 전체 화면에 고정된 하나의 canvas와 같은 입자 풀을 쓴다. 문서는 긴 scroll track을 제공하고, 스크롤 비율을 0–5.82의 장면 진행값으로 바꾼다. 오른쪽 장면 레일(모바일은 하단)과 URL hash가 같은 여섯 장면을 가리킨다.

| 장면 | 수심 | 입자가 그리는 것 | HTML |
| --- | --- | --- | --- |
| 00 수면 | 0m | 가지 위의 물총새, 가지, 수면선, 수면 아래 반짝임, 수면에 비친 새, 공중의 먼지 | 보이지 않는 제목 `Alcedo` |
| 01 홈랩 | −12m | 네트워크 트리. 가지를 따라 흐르는 입자, 분기점 노드, 선택된 경로, 끝단 원 | 문장, 주제, 링크, 개념도 캡션 |
| 02 프로젝트 | −24m | 프로젝트 위젯. 카드 테두리, 머리줄 구분선, 상태 점, `BUILD → VERIFY → DEPLOY` 파이프라인, 기술 칩, 두 버튼 | `hugo.toml` 코드, 제목, 요약, 링크 |
| 03 노트 | −36m | 노트 두 장. 접힌 모서리, 괘선, 체크 상자와 체크 표시, 두 열로 나뉜 두 번째 노트 | 번호, 제목, 요약, 링크 |
| 04 발행 | −48m | 실험 → Hugo·Velog·GitHub → 기록. 문서·말풍선·`</>`·물결 아이콘, 흐르는 신호 | 노드 이름 |
| 05 검색 | −60m | 검색 알약. 돋보기, 입력 밑줄, 전송 버튼과 화살표 | 검색 입력, 링크 |

첫 화면에는 입자 물총새만 보인다. 헤더와 장면 레일은 수면을 벗어난 뒤 나타난다. 부리 끝에서 가끔 물방울이 떨어져 수면에 파문을 만들며, 아래로 내려가라는 신호가 된다.

## 4. 잠수 (00 → 01)

잠수는 이 사이트의 대표 전환이며 스크롤에 묶여 되감을 수 있다.

1. 0–0.30: 가지 위에서 숨 쉬듯 미세하게 움직인다. 머리는 포인터 쪽으로 조금 기운다.
2. 0.30–0.45: 몸을 낮추고 꼬리를 든다.
3. 0.45–0.70: 날개를 접은 유선형으로 모핑하며 포물선을 그리며 떨어진다. 꼬리 쪽 입자가 늦게 따라와 푸른 궤적을 남긴다. 반영은 수면으로 다가온다.
4. 0.70–0.78: 입수. 수면선이 파문으로 흔들리고, 입자 물보라가 솟았다가 떨어진다. 반영이 깨진다.
5. 0.78–1.00: 카메라가 따라 내려가 수면·가지가 위로 사라진다. 입수 지점이 네트워크의 뿌리가 되고, 부리 쪽 입자부터 가지를 따라 흘러 트리를 채운다.

## 5. 입자 모핑 엔진

- **대응:** 장면마다 입자에 자리를 배정할 때, 이전 장면의 위치와 다음 장면의 자리를 x 분위로 나눈 띠 안에서 y 순서로 짝짓는다(Knothe–Rosenblatt 방식). 가까운 입자는 가까운 자리로 가고, 경로가 서로 엉키지 않는다. 대응은 레이아웃이 바뀔 때만 다시 계산한다.
- **경로:** 입자마다 공간 위치에 따른 출발 시차가 있다. 이동은 시작과 끝의 속도·가속도가 0인 5차 곡선을 따르고, sin(πt) 크기의 곡선 편차와 느린 흐름장이 더해진다. 도착하면 편차가 사라져 흔들리지 않는다.
- **구멍 없음:** 크기·밝기·색은 두 장면의 재료 값 사이에서만 보간한다. 전환 중에 입자를 투명하게 해서 이동을 가리지 않는다.
- **스크롤 평활화:** 스크롤 진행값을 임계 감쇠 스프링으로 따라가게 한다. 입자·문구·장면 레일이 같은 값을 쓴다. 스크롤을 가로채거나 스냅하지 않는다.
- **상호작용 변위:** 포인터 반발과 클릭 파문은 형태 위의 별도 변위 스프링으로 더한다. 형태 자체는 항상 정확하다.
- **반영:** 00 장면에서는 같은 입자 버퍼를 수면 기준으로 한 번 더 그린다. 반영은 아래로 갈수록 흐려지고 물결을 따라 흔들린다.
- **대체:** WebGL을 쓸 수 없으면 Canvas 2D의 1,800개 입자로 같은 장면을 그린다. 둘 다 실패하면 여섯 장면을 일반 문서 흐름으로 되돌린다. 동작 줄이기에서는 각 장면의 정지 형태만 그린다.

## 6. 문구와 크롬의 움직임

- 장면 문구는 장면 진행값에 묶인다. 들어올 때는 줄 단위로 가려진 채 아래에서 올라오고, 나갈 때는 위로 조금 흐르며 사라진다. 역방향 스크롤에서는 같은 경로를 되감는다.
- 02 장면의 코드는 위에서 아래로 드러나고, 위젯 내용은 입자 테두리가 완성된 뒤 나타난다.
- 장면 레일에는 현재 장면의 선이 길어지고 수심이 함께 표시된다.
- 입력과 링크를 조작하는 동안 장면 키보드 명령(방향키, Page Up/Down, Home, End)은 가로채지 않는다.

## 7. 정적 기록 페이지

- 목록은 번호, 제목, 요약, 날짜의 편집형 아카이브다. 행 전체가 링크이며 hover·focus에서 번호와 화살표가 반응한다.
- 글은 760px 안팎의 읽기 폭, sticky 목차와 현재 절 강조, 상단 읽기 진행선, 복사 가능한 코드와 주소, 스크롤 가능한 표를 제공한다.
- 페이지 이동은 View Transitions를 지원하는 브라우저에서 목록의 제목이 글 제목으로 이어지고, 헤더는 그대로 남는다. 지원하지 않거나 동작 줄이기에서는 일반 이동이다.
- 검색은 ⌘K·Ctrl+K·`/`로 여는 대화상자와 `/search/` 페이지가 같은 결과를 쓴다. 검색어를 강조하고 방향키로 결과를 오간다.
- 320px에서도 긴 코드·URL·표 때문에 문서 전체가 가로로 넘치지 않아야 한다.

## 8. 글 읽기 전환

홈에서 글을 열면 현재 장면의 입자가 실제 제목·설명·본문 글자의 획으로 모인 뒤, 같은 위치의 HTML 본문으로 이어진다. `article-glyphs.js`가 보이는 글자만 측정해 좌표를 만들고, 전환 시간은 `reader-motion.js`가 공유한다. 노트의 이전·다음 이동은 기존 글자가 입자로 흩어졌다가 다음 글의 획으로 모인다. 주소·제목·canonical은 글에 맞게 바뀌고 Back/Forward가 글과 읽던 위치를 복원한다. 샘플링에 실패하면 HTML끼리 교차해 나타나는 전환으로 대체한다.

## 9. 성능과 접근성

- 입자는 데스크톱 19,000개, 모바일 10,000개, Canvas 대체 1,800개. 기기 픽셀 비율은 최대 2로 제한한다. 탭이 숨겨지거나 읽기 화면이 열리면 RAF를 멈춘다.
- canvas는 `aria-hidden`이다. 현재 장면이 아닌 section은 `inert` 처리해 초점이 들어가지 않게 한다.
- 프로그램으로 옮긴 제목 초점에는 장식 테두리를 그리지 않는다. 키보드 초점은 항상 보인다.
- JavaScript가 없으면 여섯 장면이 일반 문서로 읽히고, 모든 글은 정적 URL로 열린다.
