# Alcedo 챕터 모션 조사와 수정 근거

2026-09-27. 범위: 기존 여섯 장면의 레이아웃·글꼴·완성된 입자 형태를 유지하고, 장면 사이의 움직임만 수정한다.

## 실제로 잘못된 부분

- `e33bb8a`의 1→2 경계에서 다음 장면의 시작 알파가 0이었다. 실제 WebGL 업로드를 추적하면 진행도 2.003에서 전경 입자의 `alpha × size²` 합이 0이었다.
- 2→3에서는 이동 중 알파를 낮춘 뒤, 목표까지 남은 거리에 따라 다시 4%까지 줄였다. 진행도 2.40의 합 7,461이 2.90에서 111로 떨어졌다. 이동을 구현하는 대신 가린 것이다.
- 3→4, 4→5에는 연결된 형태의 좌표를 그대로 보간하는 예전 경로가 남았다. 페이지 테두리와 선이 휘어 움직였다.
- 기존 테스트는 빠른 전환에서 입자가 희미해지는 것을 성공으로 판정했다. 정지 화면만 보존했으며 실제 연속 프레임의 실패를 검증하지 못했다.

수치는 전체 화면 밝기가 아니라 전경 입자 렌더 버퍼의 상대적인 출력량이다.

## 조사에서 구분한 사실과 판단

- [Webflow, 2026 웹 디자인 경향](https://webflow.com/blog/web-design-trends-2026), 2026-01-08: 획일적인 자동 생성 결과에 대한 대안으로 의도적인 고유 시각 체계를 강조한다. 여기서는 새 유행 효과를 추가하기보다 원래의 입자 표현을 일관되게 완성하는 근거로 적용한다.
- [Figma, 2026 웹 디자인 경향](https://www.figma.com/resource-library/web-design-trends/): 타이포그래피와 모션을 리듬·이야기·시선 유도의 수단으로 설명한다. 조용한 기술 기록에는 과장된 튕김보다 연속적인 움직임이 맞는다는 것은 이 프로젝트에 대한 디자인 판단이다.
- [Nielsen Norman Group, The Role of Animation and Motion in UX](https://www.nngroup.com/articles/animation-purpose-ux/), 2020-01-12: 상태 변화를 설명하는 짧고 절제된 모션과, 사용자를 기다리게 하는 장식적 전환을 구별한다. 스크롤을 잠그거나 별도 재생을 강요하지 않는 기준으로 사용한다.
- [W3C, Animation from Interactions](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html): 비필수 상호작용 모션을 비활성화할 수 있어야 한다는 AAA 기준이다. 모션 감소 설정에서는 중간 경로를 생략한다.
- [Awwwards 평가 기준](https://www.awwwards.com/about-evaluation/): 디자인 40%, 사용성 30%, 창의성 20%, 콘텐츠 10%. 수상은 업계 평가이며 대중적 선호를 증명하지 않는다.
- [Joseph Santamaria 제작 후기, Codrops](https://tympanus.net/codrops/2026/04/28/more-than-a-portfolio-building-a-scroll-driven-3d-world-with-something-to-say/), 2026-04-28 및 [실제 사이트](https://joseph-san.com/): 장면·카메라·스크롤을 한 흐름으로 조율한 제작 사례. 실제 화면과 스크롤을 확인했다. 3D 배경이나 로딩 진입 화면을 이 블로그에 가져오지 않고, 하나의 진행도로 요소들을 조율하는 원칙만 참고했다.

이 자료들은 특정 파티클 효과가 사람들에게 인기 있다는 근거가 아니다. 이 프로젝트의 기준은 사용자가 제공한 영상, 기존 장면, 직접적인 요구다. 이 구현이 'AI 같다'는 판단도 기술 출처 판별이 아니라, 임의의 효과 반복·요구 불이행·검증 부족에 대한 디자인 비평으로 한정한다.

## 수정한 모션

1. 기존 `_target()` 및 HTML/CSS를 그대로 두고, 정지한 여섯 장면의 전체 입자 집합을 원본과 비교한다.
2. 공간 순서로 입자의 다음 자리를 연결한다. 위치가 가까운 재료부터 이어 받아 전체 테두리가 뒤틀려 이동하지 않게 한다.
3. 모든 다섯 경계에서 작은 입자별 시차, 풀림, 곡선 이동, 모임을 사용한다. 가지·페이지·노드에 따라 흐름 방향이 달라진다.
4. 전환을 가리는 두 알파 배율을 삭제한다. 알파와 크기는 원래 두 장면의 재료 값 사이에서만 바뀐다.
5. DOM과 캔버스가 같은 화면 진행도를 쓴다. 빠른 스크롤과 탐색 이동도 이 연속 경로를 따라가며, 역방향 입력으로 즉시 되돌릴 수 있다.
6. 모션 감소, 초기 딥링크, 리사이즈, 글 읽기에서 복귀할 때는 해당 상태로 바로 맞춘다.

## 검증 기준

- 원본 `3adaff2`의 geometry/target 해시와 여섯 정지 장면의 전체 입자 집합 일치.
- 다섯 경계의 시작·경계선·끝 좌표 연속성과 순방향/역방향 일치.
- 실제 `_update()`를 연속 호출해 유한한 좌표와 전경 입자 출력량 유지 확인.
- 실제 브라우저에서 연속 스크롤, 즉시 역방향, 빠른 이동, 탐색, 읽기 복귀, 모바일, 모션 감소 및 Canvas 대체 렌더러 확인.

자동 테스트 통과를 미적 완성도의 증명으로 사용하지 않는다. 중간 프레임과 실제 동작을 별도로 검토한다.

## 이번 실행에서 확인한 결과

- `make check`: Python 4개, 모션 회귀 검사 10개, Hugo 빌드 및 생성된 HTML 18페이지·링크·canonical 검사 통과.
- 데스크톱 1440×1000, 모바일 390×844에서 각 경계의 중간 화면을 저장해 검토. 가로 스크롤 넘침 0.
- 1→3 연속 이동을 실제 WebGL 캔버스로 녹화. 초기 수정의 퍼짐이 지나치게 넓어 보이는 구간을 확인하고 개별 입자의 퍼짐 폭을 줄였다.
- 전체 역방향 WebGL 추적에서 각 경계의 전경 `alpha × size²` 최솟값: 0→1 20,381 / 1→2 7,461 / 2→3 7,461 / 3→4 13,624 / 4→5 19,787. 서로 다른 장면의 원래 밀도 차이가 있으므로 경계 간 절대값 비교를 품질 점수로 해석하지 않는다. 기존의 0 또는 111까지 내려가는 숨김은 제거됐다.
- 실제 휠 입력 후 즉시 반대 입력, `#explore`로 이동하는 중 리사이즈를 실행해 목적지 유지 확인.
- 노트 열기 → 다음 글 → 닫기 후 `#notes`와 정상 렌더링 복귀 확인. 수집한 페이지 오류 0.
- OS 모션 감소 에뮬레이션에서 RAF 정지 및 장면 직접 전환 확인. WebGL을 비활성화한 모바일 390×844에서 Canvas 1,800개 입자 렌더링 확인.

검증 환경은 Ego Chromium과 기기 크기/설정 에뮬레이션이다. 실제 iPhone Safari나 모든 저사양 기기를 검증한 결과는 아니다. 녹화 파일은 캔버스 입자 레이어만 포함하며 전체 HTML 화면 녹화가 아니다.
